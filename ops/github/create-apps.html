GitHub App di devloop

Una pagina per creare le GitHub App di un insieme di devloop (ops/README.md, «2. GitHub App»). Si compilano i tre campi; la pagina mostra i valori da scrivere nei parametri del progetto e un pulsante per ogni app che manca. Nessuna chiamata a GitHub prima del clic su un pulsante, nessuna credenziale letta.

App dell'insieme

Per un insieme nuovo si lasciano tutte da creare. Per un insieme che esiste già si segnano quelle che ha (le si vede nelle impostazioni delle GitHub App del proprietario): la pagina crea solo le altre. coordinator solo se il progetto ha il coordinatore (passo 10), merger solo se devloop mergia ([merge] mode strict o auto).

RuoloL'insieme l'ha giàPermessi

Valori dei parametri

Da scrivere nel file dei parametri del progetto (ops/params.env o quello di --params), uguali a quelli dell'insieme: con un errore di battitura le app avrebbero nomi che check-host.sh e l'overlay non trovano.




App da creare


Per ciascuna: Crea, conferma su GitHub, poi entro un'ora lo scambio del
code sull'host (ops/README.md, «2. GitHub App», punto 2: la risposta contiene
la chiave privata, che va direttamente nella key_dir, mai stampata né copiata
altrove), infine Install App → Only select repositories → il solo repository
gestito. Le app che l'insieme ha già si installano anche sul repository nuovo, dalle loro
impostazioni (ops/README.md, «Insieme di app per repository o condiviso»).
